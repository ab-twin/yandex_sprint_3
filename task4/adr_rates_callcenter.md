### **Название задачи:**
Передача ставок в кол-центр и подключение партнёрского кол-центра

### **Автор:**
Команда цифровой трансформации / ИТ-архитектор

### **Дата:**
01.01.2025

---

### **Функциональные требования**
| **№** | **Действующие лица или системы**        | **Use Case**                                         | **Описание**                                                                 |
|:----:|----------------------------------------|------------------------------------------------------|------------------------------------------------------------------------------|
| 1    | Сотрудник кол-центра                   | Просмотр актуальных ставок                          | Получает доступ к депозитным ставкам через интерфейс CRM                    |
| 2    | Сотрудник партнёрского кол-центра      | Получение файла со ставками                         | Загружает актуальный XLS/CSV-файл с условиями депозитов                    |
| 3    | Система кол-центра                     | Интеграция с хранилищем ставок                      | Получает данные в реальном времени или по расписанию                        |
| 4    | Система выгрузки ставок                | Подготовка файла для партнёрского кол-центра        | Экспортирует ставки в файл и размещает по протоколу передачи                |

---

### **Нефункциональные требования**
| **№** | **Требование**                                                                       |
|:----:|---------------------------------------------------------------------------------------|
| 1    | Обновление ставок в кол-центре должно происходить не реже, чем раз в час              |
| 2    | Выгрузка для партнёрского кол-центра — 1 раз в день в надёжном формате (CSV/XLSX)     |
| 3    | Безопасная передача файлов — SFTP/шифрование                                          |
| 4    | Отказоустойчивость сервиса выгрузки ставок                                            |
| 5    | Повторное использование уже реализованного хранилища ставок                          |

---

### **Решение**

#### Диаграмма контекста (C4 — уровень System Context)
[Context.puml](Context.puml)

#### Диаграмма компонентов (C4 — уровень Container/Component)
[Container.puml](Container.puml)

#### Технологии
- API: REST с авторизацией
- Формат выгрузки: CSV или XLSX
- Средства планирования задач: cron/Quartz/.NET scheduler

---

### **Альтернативы**
- Вручную отправлять Excel-файл по почте каждый день  
  ❌ Зависимость от оператора, нет логирования, высокий риск ошибок
- Использовать только API для всех кол-центров  
  ❌ Невозможно из-за внешних ограничений со стороны партнёра

---

### **Недостатки, ограничения, риски**
- Необходимость организации безопасного канала выгрузки (SFTP, VPN)
- Разграничение доступа к API ставок (только чтение, без возможности подмены)
- Периодичность обновлений ставок — компромисс между актуальностью и нагрузкой

---

### **Список крупных задач по системам**

#### Хранилище ставок
- Расширение API с правами только для чтения
- Ограничение данных по ролям (CRM / выгрузка / ИБ)

#### CRM кол-центра
- Добавление вкладки «Актуальные ставки»
- Интеграция с API хранилища

#### Сервис выгрузки ставок
- Разработка сервиса генерации файла (по расписанию)
- Формирование CSV/XLSX-файла
- Организация защищённой передачи (например, по SFTP)

#### Система партнёрского кол-центра
- Подключение к источнику получения файла
- Визуализация или доступ к данным через внутреннюю систему
